## 三、缺陷与回归用例（含复现步骤）

> **状态说明**：BUG-01～BUG-16 已在测试窗口内部署的 E-24 修复构建中解决，并已逐项复核通过；以下保留当时的复现步骤，作为回归用例。BUG-17 与 BUG-18 在最终构建（`index-BQUtyec5.js`）上仍然存在。

### BUG-01【高·已修复】保存源设置会把“API 地址”清空，导致漫画源整体失效

**影响**：在源设置页只改“图片质量”并保存，也会把必填的 API 域名写成空串；此后该源所有搜索/详情/阅读请求都会失败（DNS 解析 `api` 主机）。

**复现步骤**
1. 以 `admin` 登录，打开 `/sources/copy_manga?tab=settings`。
2. 观察“API地址”输入框为**空**（默认值 `api.copy2000.online` 未回填）。
3. 将“图片质量”从“低 (800)”改为“中 (1200)”，点击“保存”。
4. 打开“检查可读性”标签，点击“检查”；或在 `/search` 用拷贝漫画搜索“海贼”。

**实际结果**
- 检查结果：`失败 · 阶段: catalog`，`SOURCE_ERROR(502): https://api/v3/h5/homeIndex: Dns Failed: resolve dns name 'api:443'`。
- 接口回读：`GET /api/sources/copy_manga/settings` → `values: {"base_url":"","image_quality":"1200"}`。

**期望结果**：空输入应保留/回填默认域名，或保存时阻止空值并提示；保存无关选项不应破坏源。
**恢复验证**：把 API 地址填回 `api.copy2000.online` 保存后，`GET /api/search?source=copy_manga&q=海贼` 恢复 200、返回 30 条。

**数据核对**
- `GET /api/explore?source=copy_manga&page=1`：`pages[0].data` 中 51 本漫画**全部没有 `sourceKey` 字段**（只有 `cover/id/subTitle/tags/title`）。
- `GET /api/explore?source=zaimanhua&page=1`：20 本漫画全部缺少 `sourceKey`。
- 对照 `GET /api/explore?source=nhentai&page=1`（`mixed` 类型）：30 本漫画全部带 `sourceKey: "nhentai"`，点击正常。
- 源能力统计：33 个启用 explore 的源中，只有 nhentai 使用 `mixed` 类型；其余 32 个使用 `singlePageWithMultiPart` / `multiPartPage` / `multiPageComicList`，均复现。

**根因定位**
- 后端 `backend/lib/services/comic_service.dart` 的 `explore()`：仅当 `type == 'mixed'` 时调用 `_mixedExplore()` 归一化（其中 `_comics()` 会补 `sourceKey`）；其他类型直接返回源脚本原始 JSON：`'data': type == 'mixed' ? _mixedExplore(data, sourceKey) : data`。
- 前端 `frontend/src/routes/ExplorePage.tsx` 的卡片点击使用 `comicPath(comic.sourceKey, comic.id)`；数据没有 `sourceKey` 时拼出 `undefined`。`ComicCard` 的封面代理 `coverUrl(comic.cover, comic.sourceKey, comic.id)` 也丢失了源上下文（公开封面仍能显示，需鉴权的源可能受影响）。
- 同类列表接口（search/category/favorites/history/read-later/image-favorites）均已核对，`sourceKey` 齐全，问题仅限 Explore 的原始 payload。

**期望结果**：发现页所有卡片均跳转到 `/comic/{当前源key}/{id}`。
**建议修复**：后端对所有 explore 类型统一走 `_comics()` 归一化并注入 `sourceKey`；或前端使用当前页面的 `sourceKey` 拼接：`comicPath(sourceKey, comic.id)`（改动更小，可立即止血）。
**最终构建复核（2026-10-21 晚）**：在 E-24 修复构建 `index-BQUtyec5.js` 上再次复现，仍跳转 `/comic/undefined/naoodngxueshenghui`；接口仍返回 51/51 无 `sourceKey`。证据截图：[explore-undefined](screenshots/usage-2026-10-21-explore-undefined.png)。
